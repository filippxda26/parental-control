# Parental Control for OpenWrt

[![Build OpenWrt 25.12.5 APK](https://github.com/filippxda26/parental-control/actions/workflows/build.yml/badge.svg)](https://github.com/filippxda26/parental-control/actions/workflows/build.yml)
[![OpenWrt](https://img.shields.io/badge/OpenWrt-25.12.5-00B5E2?logo=openwrt&logoColor=white)](https://openwrt.org/)
[![Language](https://img.shields.io/badge/Language-C-00599C?logo=c&logoColor=white)](https://github.com/filippxda26/parental-control)

Родительский контроль для **OpenWrt** с веб-интерфейсом, ограничением времени и скорости, ночной блокировкой, Whitelist по расписанию и управлением отдельными устройствами в локальной сети.

Проект работает как единый сервис: основной daemon управляет правилами **nftables**, отслеживает активность устройств, хранит состояние и одновременно запускает встроенный веб-интерфейс.

## Возможности

- создание отдельных профилей устройств;
- определение устройств по MAC-адресу и Hostname;
- привязка дополнительных MAC-адресов к одному профилю;
- автоматическое обнаружение устройств через DHCP/ARP;
- дневной лимит использования;
- лимит одной сессии;
- обязательное время отдыха между сессиями;
- ночная блокировка по расписанию;
- Whitelist доменов и IP по расписанию;
- Blacklist доменов и IP для постоянной точечной блокировки;
- ручная блокировка и разблокировка;
- добавление бонусного времени;
- сброс статистики за текущий день;
- ограничение скорости через nftables;
- сохранение текущего состояния после перезапуска;
- история действий;
- веб-интерфейс без внешних JavaScript-фреймворков;
- WebSocket для обмена данными между интерфейсом и daemon;
- автоматическая сборка OpenWrt APK через GitHub Actions.

## Интерфейс

Сервис открывает два TCP-порта:

| Порт | Назначение |
| --- | --- |
| `5000` | основной Web UI и WebSocket `/ws` |
| `8081` | отдельная страница привязки устройства по адресу `/connect/<имя профиля>` |

После установки основной веб-интерфейс по умолчанию доступен по адресу:

~~~text
http://IP_РОУТЕРА:5000/
~~~

Например:

~~~text
http://192.168.1.1:5000/
~~~

Страница привязки устройства работает через порт `8081`, например:

~~~text
http://192.168.1.1:8081/connect/имя-профиля
~~~

Она пытается определить IP/MAC подключившегося устройства и привязать его к уже существующему профилю с указанным именем.

В основном интерфейсе можно добавлять и редактировать устройства, включать ограничения, смотреть использованное время, запускать перерыв, выдавать бонусное время и вручную блокировать доступ.

> [!IMPORTANT]
> По умолчанию основной веб-интерфейс слушает `0.0.0.0:5000`, а сервис привязки — `0.0.0.0:8081`. В проекте нет отдельной формы логина/пароля, поэтому **не открывайте порты 5000 и 8081 в Интернет/WAN**. Оставляйте доступ только из доверенной локальной сети или самостоятельно добавьте защищённый reverse proxy/VPN.

## Установка APK

GitHub Actions собирает пакет для **OpenWrt 25.12.5 x86_64** только при ручном запуске через **Run workflow**. Автоматический запуск при `push` и `pull_request` отключён. После успешной ручной сборки APK публикуется в GitHub Releases.

### Автоматическая загрузка и установка последнего APK

На OpenWrt можно одной командой скачать APK из последнего GitHub Release и сразу установить его через `apk add --allow-untrusted`:

~~~sh
wget -qO- https://raw.githubusercontent.com/filippxda26/parental-control/main/download-apk.sh | sh
~~~

Если репозиторий уже скачан:

~~~sh
sh ./download-apk.sh
~~~

Чтобы сохранить APK в другую директорию перед установкой, передайте её первым аргументом:

~~~sh
sh ./download-apk.sh /tmp
~~~

Скрипт автоматически находит последний Release, выбирает файл `parental-control-*.apk`, скачивает его через доступный `wget` или `curl`, а затем выполняет `apk add --allow-untrusted` для скачанного файла. Команду нужно запускать с правами, достаточными для установки пакетов.

1. Откройте раздел [Releases](https://github.com/filippxda26/parental-control/releases).
2. Скачайте `parental-control-<version>.apk`.
3. Передайте файл на роутер.
4. Установите пакет:

~~~sh
apk add --allow-untrusted ./parental-control-<version>.apk
~~~

5. Включите автозапуск и запустите сервис:

~~~sh
/etc/init.d/parental-control enable
/etc/init.d/parental-control start
~~~

6. Откройте в браузере:

~~~text
http://IP_РОУТЕРА:5000/
~~~

Флаг `--allow-untrusted` отключает проверку доверия к подписи для этого локального пакета. Используйте его только для APK, которому доверяете.

## Управление сервисом

~~~sh
# Запуск
/etc/init.d/parental-control start

# Остановка
/etc/init.d/parental-control stop

# Перезапуск
/etc/init.d/parental-control restart

# Автозапуск
/etc/init.d/parental-control enable

# Отключить автозапуск
/etc/init.d/parental-control disable
~~~

Основной процесс:

~~~text
/usr/sbin/parental-control
~~~

Отдельный `parental-control-web` больше не требуется: веб-сервер встроен в основной процесс.

## Конфигурация

Основные файлы:

| Путь | Назначение |
| --- | --- |
| `/etc/parental-control/devices.json` | профили и ограничения устройств |
| `/etc/parental-control/settings.json` | настройки веб-сервера |
| `/var/lib/parental-control/state.json` | текущее состояние и счётчики |
| `/var/lib/parental-control/history.json` | история действий |
| `/var/run/parental-control.sock` | локальный Unix socket |
| `/var/run/parental-control.nft` | временный набор правил nftables |

Настройки основного веб-сервера по умолчанию:

~~~json
{
  "web_port": 5000,
  "bind_address": "0.0.0.0"
}
~~~

Порт `5000` настраивается через `settings.json`. Порт привязки `8081` в текущей версии задан непосредственно в `src/parental-control-web.c` и использует тот же `bind_address`.

После ручного изменения конфигурации рекомендуется перезапустить сервис:

~~~sh
/etc/init.d/parental-control restart
~~~

## Как работают ограничения

### Дневной лимит

Сервис учитывает активное использование сети устройством. После достижения `daily_limit_minutes` доступ блокируется до сброса дневного состояния либо выдачи дополнительного времени.

### Сессия и отдых

Лимит сессии считается **по фактической сетевой активности устройства**, а не просто по времени с момента подключения. Счётчик `session_limit_minutes` увеличивается, когда сервис обнаруживает трафик устройства; если трафика нет и окно активности истекло, время сессии не расходуется.

После накопления заданного количества минут активного использования автоматически начинается перерыв на `break_minutes`.

### Ночная блокировка

При включённом `night_enabled` доступ блокируется внутри заданного временного интервала. Поддерживается расписание, переходящее через полночь, например `22:00 → 08:00`.

### Whitelist

В заданное время устройству можно разрешить доступ только к выбранным доменам или IP-адресам. Доменные имена резолвятся в IP-адреса и правила периодически обновляются.

### Blacklist

При включённом `blacklist_enabled` сервис блокирует для устройства только адреса из `blacklist_entries`, не отключая остальной Интернет. Можно указывать IPv4, IPv6 и доменные имена. Домены резолвятся в IP-адреса, а правила автоматически обновляются примерно раз в 5 минут. Если один и тот же адрес одновременно попал в Whitelist и Blacklist, блокировка Blacklist имеет приоритет.

### Ограничение скорости

При включённом `speed_limit_enabled` сервис создаёт nftables-правила с лимитом трафика для MAC-адресов профиля.

## Сетевые правила

Проект использует таблицу:

~~~text
inet parental_control
~~~

При остановке сервиса его таблица nftables удаляется, а временные файлы очищаются.

Правила автоматически пересобираются при изменении состояния устройства, ручной блокировке, начале/окончании перерыва и изменении Whitelist.

## WebSocket и внутренний API

Браузерный интерфейс подключается к:

~~~text
/ws
~~~

Обычные HTTP-запросы к `/api/*` на веб-порту специально отключены и возвращают требование использовать WebSocket.

Основной daemon внутри поддерживает операции для:

- получения состояния и списка устройств;
- обнаружения устройств;
- просмотра истории;
- создания, изменения и удаления профиля;
- блокировки/разблокировки;
- запуска перерыва;
- выдачи бонусных минут;
- сброса состояния за день;
- привязки найденного устройства к профилю.

## Сборка на Linux

Для обычной локальной проверки C-кода нужны компилятор, `json-c` и pthread.

~~~sh
make
~~~

Результат:

~~~text
./parental-control
~~~

~~~sh
make clean
~~~

## Сборка OpenWrt-пакета

Исходники пакета находятся в:

~~~text
openwrt-package/
~~~

Для ручной сборки через OpenWrt SDK каталог можно поместить в `package/parental-control`, включить пакет в конфигурации SDK и выполнить:

~~~sh
make package/parental-control/compile V=s
~~~

Текущий GitHub Actions workflow использует OpenWrt SDK **25.12.5 x86_64**, проверяет синхронизацию исходников, компилирует проект с предупреждениями как ошибками и публикует готовый APK.

При ручном запуске через **Run workflow** GitHub Actions предлагает указать версию и release пакета:

~~~yaml
workflow_dispatch:
  inputs:
    pkg_version:
      description: 'Версия, например 1.0.0'
      required: true
      default: '0.1.0'
      type: string
    pkg_release:
      description: 'Релиз пакета, например 1'
      required: true
      default: '1'
      type: string
~~~

Перед сборкой workflow подставляет эти значения в `PKG_VERSION` и `PKG_RELEASE` внутри `openwrt-package/Makefile`. Если оставить поля без изменений, используются значения по умолчанию `0.1.0` и `1`.

## Разработка

Основные исходники находятся в `src/`, а копии для OpenWrt-пакета — в `openwrt-package/src/`.

GitHub Actions проверяет, что эти версии совпадают, поэтому после изменения исходников не забывайте синхронизировать обе директории. То же относится к `files/` и `openwrt-package/files/`.
